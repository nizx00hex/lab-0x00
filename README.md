# C Programming Practice Lab

This repository contains my structured C programming practice while studying *Hacking: The Art of Exploitation (2nd Edition)* alongside independent learning.

The goal is not just learning syntax, but understanding how C behaves at a low level — memory, stack, pointers, and system internals.

---

## 🎯 Objective

- Build strong fundamentals in C programming
- Understand memory layout (stack, heap, data, text)
- Master pointers and low-level memory manipulation
- Learn debugging using GDB
- Develop foundations for reverse engineering and system-level programming

---

## 📚 Learning Sources

- *Hacking: The Art of Exploitation (2nd Edition)*
- Linux system experimentation
- GDB debugging practice
- Self-directed C programming exercises

---

## 🧠 Key Topics

- Variables, loops, and functions
- Pointers and pointer arithmetic
- Arrays and string memory representation
- Stack frames and function calls
- Memory layout of processes
- Debugging with GDB
- Introductory vulnerability concepts (lab-only)

## 📁 Repository Structure

Code is organized using hexadecimal-style progression for structured learning:
.
├── taoe/                # Notes / reference material from TAOE
│
├── 0x00                 # Main program (compiled output binary)
├── 0x00-forloop.c       # Source code (for-loop practice)
│
├── 0x01
├── 0x02-size.c
└── README.md


---

## 🧾 Naming Convention

- `0x00`, `0x01`, `0x02` → Learning stages (hex progression)
- `*-pointer.c`, `*-memory.c` → Topic-specific exercises inside each stage
- Compiled binaries (`a.out`, `0x00`, etc.) are build artifacts and should not be committed
